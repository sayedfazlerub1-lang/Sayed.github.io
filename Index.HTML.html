What the testing actually looks like

No public repo yet, so here's a representative test case, defect report, and automation script — modeled on the login and checkout flows from the SEED Infotech e-commerce project — to show the work rather than just describe it.

TC-014 · authenticationpass

Login with valid credentials

setupUser has an active, registered account
steps
  1. Navigate to the login page
  2. Enter a valid registered email
  3. Enter the correct password
  4. Click "Login"
expectedUser is authenticated and redirected to the homepage within 2s, with the session persisted
BUG-231 · checkoutreopened → fixed

Cart total ignores applied coupon

severitymajor priority: high
steps
  1. Add 2 items to the cart
  2. Go to checkout and apply a valid coupon code
  3. Observe the order total
expectedDiscounted total reflects immediately after the coupon is applied
actualTotal stays unchanged until the page is manually refreshed
LoginTest.java · Selenium + TestNGautomates TC-014
// Automates the login test case above; catches BUG-231-style regressions on rerun
@Test
public void verifyLoginWithValidCredentials() {
    driver.get(BASE_URL + "/login");
    driver.findElement(By.id("email")).sendKeys("test.user@example.com");
    driver.findElement(By.id("password")).sendKeys("Passw0rd!");
    driver.findElement(By.cssSelector("button[type='submit']")).click();

    WebElement dashboard = new WebDriverWait(driver, Duration.ofSeconds(10))
            .until(ExpectedConditions.visibilityOfElementLocated(By.id("dashboard-header")));

    Assert.assertTrue(dashboard.isDisplayed(), "Dashboard should load after login");
    Assert.assertEquals(driver.getCurrentUrl(), BASE_URL + "/dashboard");
}
